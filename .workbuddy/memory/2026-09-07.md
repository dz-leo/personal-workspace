## 账本打不开 8765 → 后端进程被回收（重要环境限制）

### 现象
用户反馈 `http://127.0.0.1:8765/` 无法打开。

### 诊断
- MySQL 正常（uptime 2.5 天，数据完好：流水 0 / 账户 7）
- 8765 端口**无监听** → 后端进程死了，不是数据库问题

### ⚠️ 关键结论：本环境无法启动「持久进程」
依次试了三种方式，**全部失败**：
1. `run_in_background` 起 server.py —— 会话结束即被回收（已复发两次）
2. `nohup ... &` + `disown` —— Bash 工具调用返回时进程照样被杀（实测起完 HTTP 200，下一次 curl 就 HTTP 000）
3. `launchctl load` / `launchctl bootstrap gui/$UID` —— 沙箱内**和** `dangerouslyDisableSandbox` 外都报
   `Bootstrap failed: 5: Input/output error`（拿不到 GUI session / Mach bootstrap 命名空间）

**结论：要让服务长期存活，必须由用户在自己的终端里执行。我这边只能起「当前会话内有效」的临时服务。**
以后遇到同类需求（起本地 server、守护进程），直接给用户命令/脚本，别再反复尝试重启。

### 已交付
- `ledger/start.command`（已 `chmod +x`）—— 双击即用：检测端口 → 起后端 → 自动开浏览器 → 打印本机/手机访问地址。
  限制：终端窗口关掉服务就停。
- `~/Library/LaunchAgents/com.dazhi.ledger.plist`（已写好，未注册成功）——
  Label `com.dazhi.ledger`，RunAtLoad + KeepAlive(true) + ThrottleInterval 10，日志 /tmp/ledger-server.log(.err)。

### 给用户的根治命令（他自己终端跑一次，终身有效）
```bash
lsof -nP -iTCP:8765 -sTCP:LISTEN -t | xargs kill -9 2>/dev/null
launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.dazhi.ledger.plist
brew services start mysql@8.0     # 让 MySQL 也开机自启，否则重启后账本连不上库
launchctl list | grep dazhi.ledger   # 验证
```

- pymysql 只在 venv：`/Users/dazhi/.workbuddy/binaries/python/envs/default/bin/python`
- `ps` 在该沙箱下 `operation not permitted`；用 `lsof -nP -iTCP:<port> -sTCP:LISTEN -t` 拿 PID
