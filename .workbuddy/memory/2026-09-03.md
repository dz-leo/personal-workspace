## 分类体系重构：三通道 + 自定义分类

- 用户发来**微信记账本 3 张截图**（支出 20 项 / 入账 9 项 / 不计入收支 3 项），要求账本分类**参照微信**且**支持自定义新增**。截图存于 `ledger/references/wechat-ledger-categories/`。
- 分类模型改三通道：`expense`（支出）/ `income`（入账）/ `transfer`（不计入收支），命名对齐微信（生活缴费/教育/其他人情等）。
- **关键：`transfer` 不计入统计**——统计只查 expense/income，自动隔离，房贷/车贷/信用卡还款/网贷本金走「借还款」，利息走正常消费。
- 自定义分类：表单「+新增」→ 弹窗选图标+颜色+命名 → 存 `settings.categories`（`custom:true`）；自定义分类按钮右上角 × 删除（二次确认），删除后历史记录兜底归「其他」。
- 补 pet 图标（之前误用 debt 图标）；示例数据 20→22 条（加 2 条 transfer：信用卡还款 3500 / 房贷 4800）。
- 冒烟测试 89→92 全过（新增：新增分类即时可选、删除二次确认+历史兜底、不计入通道隔离）。分类改名后测试断言基数同步更新（示例 22、支出分类 20）。

### ⚠️ 教训（重要）
用户问「怎么分类」是**操作层问题**（选哪个 Tab），不是**技术层问题**（要不要改统计代码）。上一轮自作主张改统计口径被纠正——这次只动分类体系与表单，统计因三通道天然隔离，**不碰统计口径**。下次遇到"怎么分类/怎么记"类问题，先答操作法，别直接改代码。

### 关键设计
- **账户模型升级为对象数组**（id/kind/initBalance/creditLimit/billDay/repayDay/cardTail/inTotal/archived/sort/note），记录里 `account`/`toAccount` 存**账户 id**（与 MySQL 一致）。旧数据（账户为名字数组、record.account 存名字）首次加载 `migrateAccountsIfNeeded()` 自动迁成对象+id 映射，不丢历史。
- **余额实时派生不落库**（防漂移）：`余额 = 初始余额 + 入账 − 支出 − 转出 + 转入`；前端 `accountBalance()/netWorth()` 与 `server.py`/SQL 同公式，双向核对一致。
- **净资产 = 总资产 − 总负债**；信用类(kind='credit')负数余额记负债。
- **账户间转账**：`transfer` 类型 + account(转出)/toAccount(转入)，不进收支统计但改余额；「余额调整对账」生成 `adjust` 分类 transfer 流水。
- **远程存储适配器**：`RemoteAdapter`（http(s) 走 MySQL 后端全量快照 + 防抖 500ms POST + 本地镜像兜底）+ `LocalAdapter`（localStorage）。`mode:'auto'`：http→Remote，file://→Local。`RemoteAdapter.load` 兼容 `{ok,data:快照}` 与直接快照两种返回。
- **移动 H5**：底部 Tab `.mnav`（日/周/+/月/资产）、`position:fixed` 全屏弹层、安全区 `env(safe-area-inset-bottom)`、`100dvh`、`<900px` 媒体查询启用。
